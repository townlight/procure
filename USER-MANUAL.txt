Townlight Procurement User Manual
========================

For Non-Technical Users
-----------------------

Townlight Procurement helps city staff keep solicitation drafts, proposal notes, exception flags, scoring summaries, staff review queues, board memo inputs, Townlight Meetings/Contracts context references, and award-packet records organized.

Current state: 0.3.0 procurement support and staff review queue runtime. Townlight Procurement can optionally save generated RFP drafts, award-packet checklists, and staff review queue records when IT configures TOWNLIGHT_PROCUREMENT_WORKPAPER_DB_URL. Staff-only review routes also require TOWNLIGHT_PROCUREMENT_STAFF_API_KEY.

Townlight Procurement does not provide official vendor evaluation decisions, legal advice, live vendor portals, live LLM calls, e-procurement submission portals, award decisions, or procurement system-of-record updates. Staff own every decision.

For IT and Technical Staff
--------------------------

Townlight Procurement is a FastAPI Python package pinned to the published townlight-core==1.3.0.dev2 release wheel. It exposes RFP draft, proposal comparison, exception extraction, scoring summary, award packet, procurement-review context, adversarial local mock, and staff review queue endpoints.

Run:

python -m pip install git+https://github.com/townlight/core.git@3021821bf9a92c790a399ad12aed821d65b09105
python -m pip install -e ".[dev]"
python -m pytest -q
bash scripts/verify-release.sh

Architecture
------------

Townlight Procurement depends on Townlight Core. Townlight Core does not depend on Townlight Procurement. Townlight Procurement v0.3.0 uses deterministic sample procurement data plus optional staff-gated persistence, review-required context packets for Townlight Meetings/Contracts references, staff review queue records, and adversarial local mocks for integration-depth validation.
